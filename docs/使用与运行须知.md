# FREE-BBS Agent 使用与运行须知

本文说明 FREE-BBS Agent 在最终用户、开发联调和生产部署三种场景下的使用方式。

## 一、最终用户须知

最终用户只需要访问 FREE-BBS 网站：

```text
https://www.free-bbs.cn
```

登录后进入：

```text
问问 Max
```

用户可以直接输入问题，例如：

```text
我想找信号与系统的课程资料
最近有什么课程通知？
我想去讨论区请教傅里叶变换
帮我找一个 FPGA 项目
```

Max 会根据问题给出回答，并展示知识库、工作台、讨论区、课程图谱、发展端或个人主页等
可点击入口。

最终用户不需要：

- 安装 Python 或 Node.js；
- 下载 Agent 仓库；
- 手动运行 `app.py`；
- 访问 `5001`、`4310` 等内部服务端口；
- 配置模型 API key 或内部服务 Token。

这些工作全部由 FREE-BBS 服务器完成。

## 二、系统调用关系

最终用户看到的是一个完整的 FREE-BBS 网站，但系统内部由多个服务协作：

```text
用户浏览器
  -> FREE-BBS 前端
  -> FREE-BBS 后端
  -> freebbs-agent
  -> Navigation / General Chat / RAG / Info / Comment Agent
```

推荐端口分配：

| 服务 | 默认地址 | 是否向公网开放 |
|---|---|---|
| FREE-BBS 前端 | `127.0.0.1:3000` | 通过 Nginx/HTTPS 对外提供 |
| FREE-BBS 后端 | `127.0.0.1:3001` | 仅通过主站 `/api` 代理 |
| freebbs-agent | `127.0.0.1:5001` | 否 |
| subagent-eeinfo | `127.0.0.1:4310` | 否 |
| MySQL | `127.0.0.1:3306` | 否 |

公网只应暴露 FREE-BBS 的 HTTPS 网站，不应直接暴露 Agent、Info 或数据库端口。

## 三、开发联调须知

本地开发时，各服务需要分别运行。

### 1. 启动 freebbs-agent

```bash
cd /home/jl2004/freebbs-agent
source .venv/bin/activate
set -a
source .env
set +a
python app.py
```

默认地址：

```text
http://127.0.0.1:5001
```

健康检查：

```text
http://127.0.0.1:5001/health
```

### 2. 启动 FREE-BBS 主站

`freebbs-web` 要求 Node.js 24 或以上，并依赖 MySQL。

```bash
cd /home/jl2004/freebbs-web
npm install
npm run start:local
```

默认地址：

```text
前端：http://127.0.0.1:3000
后端：http://127.0.0.1:3001
```

浏览器应打开：

```text
http://127.0.0.1:3000/aichat
```

不要把 `http://127.0.0.1:5001/dev/*` 当作最终用户页面。这些页面仅供 Agent 单体调试。

### 3. 启动 Info Sub-Agent

只有联调课程公告、网络学堂或 THU Info 时才需要：

```bash
cd /home/jl2004/subagent-eeinfo
export EEINFO_INTERNAL_TOKEN='<INFO_TOKEN>'
npm run demo
```

默认地址：

```text
http://127.0.0.1:4310
```

Info 内部 Token 不得填写到浏览器页面或发送给最终用户。

## 四、生产部署须知

生产环境不应由开发者在终端中长期运行 `python app.py`。应使用 systemd、容器编排平台或
等价的进程管理器维护服务。

建议服务：

```text
free-bbs-frontend.service
free-bbs-backend.service
free-bbs-agent.service
subagent-eeinfo.service
mysql.service
```

`freebbs-agent` 仓库已经提供 systemd 模板：

```text
deploy/systemd/free-bbs-agent.service
```

启用服务的示例：

```bash
sudo systemctl enable --now free-bbs-agent
sudo systemctl enable --now free-bbs-backend
sudo systemctl enable --now free-bbs-frontend
```

服务器重启后，这些服务应自动恢复。最终用户不参与任何服务启动操作。

## 五、关键配置

### freebbs-agent

```dotenv
AGENT_HOST=127.0.0.1
AGENT_PORT=5001
FREEBBS_WEB_BASE_URL=https://www.free-bbs.cn
```

本地联调时：

```dotenv
FREEBBS_WEB_BASE_URL=http://127.0.0.1:3000
```

### freebbs-web

```dotenv
AGENT_URL=http://127.0.0.1:5001
PUBLIC_WEB_URL=https://www.free-bbs.cn
```

本地联调时：

```dotenv
PUBLIC_WEB_URL=http://127.0.0.1:3000
CORS_ORIGIN=http://127.0.0.1:3000
```

### Info Agent

```dotenv
INFO_AGENT_ENABLED=true
INFO_AGENT_BASE_URL=http://127.0.0.1:4310
INFO_AGENT_INTERNAL_TOKEN=<与 EEINFO_INTERNAL_TOKEN 相同>
FREEBBS_AGENT_INTERNAL_TOKEN=<主站后端到 Agent 的独立 Token>
```

两个内部 Token 保护不同的服务边界，不应复用，也不应出现在浏览器中。

## 六、各 Agent 的用户入口

| Agent | 最终用户入口 | 说明 |
|---|---|---|
| Navigation | `/aichat` | 理解需求并生成主站跳转按钮 |
| General Chat | `/aichat` | 普通知识问答，可由 Navigation 或页面模式选择调用 |
| RAG | `/knowledge`、课程知识页 | 检索课程资料并生成带来源的回答 |
| Info | `/workbench`、`/aichat` | 查询公告、课程和校园信息，需要可信身份 |
| Comment | `/discussion` | 用户在评论中 `@max` 时触发 |

开发测试页不是正式用户入口。

## 七、故障时的预期行为

### Agent 服务不可用

主站应显示：

```text
Max 暂时不可用，请稍后再试。
```

不应把内部错误堆栈、Token 或服务地址展示给用户。

### 模型服务不可用

Navigation 应回退到规则路由，基础跳转按钮仍然可用。

### RAG 未启用

Navigation 仍可返回知识页面入口；直接调用 RAG 时应显示明确的未启用提示。

### Info 需要认证

主站应提示用户完成清华认证，并通过主站后端轮询任务状态。浏览器不得直接调用
`subagent-eeinfo` 内部接口。

## 八、安全要求

- Agent 和 Info 服务只监听 loopback 地址；
- 所有用户身份都由 FREE-BBS 后端从已验证会话中取得；
- 不信任浏览器 JSON 中自报的 UID、学号或权限；
- 内部 Token 不得进入前端代码、页面源码、Local Storage 或日志；
- Navigation 跳转链接必须使用服务端和前端双重白名单；
- 密码、验证码、Cookie 和模型 API key 不得进入 Agent 对话上下文；
- 生产环境通过 HTTPS 对外提供 FREE-BBS 网站。

## 九、验收检查

部署完成后至少验证：

1. 用户只访问 `https://www.free-bbs.cn/aichat` 即可使用 Max；
2. 用户无需知道或访问 5001、4310 端口；
3. Navigation 按钮能进入真实主站页面；
4. Agent 进程重启后主站能恢复调用；
5. 服务器重启后所有服务自动启动；
6. Agent/Info 端口不能从公网直接访问；
7. 浏览器网络请求中不出现内部 Token；
8. Agent 故障时主站显示用户可理解的错误信息。
