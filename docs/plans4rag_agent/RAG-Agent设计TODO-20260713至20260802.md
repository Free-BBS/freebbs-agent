# FREE BBS RAG-Agent 设计 TODO

> 执行周期：2026 年 7 月 13 日至 2026 年 8 月 2 日  
> 目标：在现有轻量向量 RAG 基础上，形成“知识图谱定位 → 关系扩展 → 资料检索 → 重排 → 回答 → 来源与页面跳转”的四课程 V1.0 Alpha。  
> 依据：`FREE BBS V1.0四组三周可勾选任务清单-20260713至20260802.md` 与当前 `freebbs-agent` 实现评审。  
> 边界：本阶段不建设独立评测 Agent，不生产四门课程的全部正文，不做复杂分布式向量库和外部联网检索。

## 一、设计结论

当前实现保留为底层文档检索骨架，但在线链路调整为：

```text
请求上下文
  → 课程/知识点图谱定位（唯一逻辑起点）
  → 前置、后置、应用、跨课程关系扩展
  → 在限定课程和知识点范围内检索资料
  → 去重与重排
  → 按快速问答/引导学习/深入探究模式生成
  → 返回可验证引用、图谱节点和站内跳转
```

本阶段继续使用 FAISS 即可。优先解决数据契约、索引一致性、真实 embedding、图谱定位、引用和评测问题，不在小规模语料上提前引入复杂基础设施。

## 二、必须先冻结的数据契约

### 2.1 统一课程 JSON

- [ ] 定义 `course.schema.json`，每个文件表示一门课程，顶层包含 `schema_version`、`course`、`knowledge_points`、`relations`、`materials` 和 `revision`。
- [ ] 课程字段至少包含 `course_id`、标准名称、别名、英文名、学习方向、课程版本和审核状态。
- [ ] 知识点字段至少包含 `knowledge_point_id`、章节 ID/名称/序号、课程内序号、标准名称、别名、英文名、符号名、检索关键词、一句话概览、课程语境、类型、难度、应用场景和审核信息。
- [ ] 关系独立保存为边，不在知识点中重复维护互相矛盾的前后置数组；字段至少包含 `relation_id`、`from_id`、`to_id`、`type`、`scope`、`evidence_ids`、`status`。
- [ ] 关系枚举至少支持 `prerequisite`、`successor`、`application`、`related`、`same_entity_candidate`。
- [ ] 资料字段至少包含 `material_id`、标题、来源层级、文件/页面定位、适用课程、适用知识点、版本、内容哈希、发布与审核状态。
- [ ] 来源层级枚举固定为 `official_text`、`course_material`、`quality_discussion`、`extended_content`、`external_auxiliary`，生成和展示均遵守此优先级。
- [ ] “无别名”等无值字段使用空数组或 `null`，不写字符串“无”，避免污染检索。
- [ ] 所有 ID 全局稳定；名称变化不改变 ID；内容变化通过 `revision` 和 `content_hash` 追踪。
- [ ] 提供一门先行课程、至少 20 个知识点的完整样例 JSON。

### 2.2 自动校验器

- [ ] 用 JSON Schema 校验必填字段、类型、枚举和格式。
- [ ] 增加语义校验：重复 ID、未知关系端点、孤立节点、未说明环路、同名异义冲突、无来源依据和未审核内容。
- [ ] 校验结果输出机器可读 JSON 和人员可读 Markdown，包含文件、对象 ID、字段、错误码和原因。
- [ ] 索引构建只接受校验通过或明确登记例外的版本。

### 2.3 统一 Agent 请求/响应

- [ ] 请求加入 `trace_id`、用户/会话、调用来源、页面、课程、知识点、权限上下文和 `rag_mode`。
- [ ] `rag_mode` 固定为 `quick_answer`、`guided_learning`、`deep_exploration`，默认 `guided_learning`。
- [ ] 响应统一包含 `answer`、`citations`、`graph_context`、`navigation`、`suggested_actions`、`warnings`、`error`、`trace_id` 和实际调用的 agent。
- [ ] citation 至少返回 `citation_id`、来源层级、标题、material ID、知识点 ID、原文片段、页码/章节/字符区间、版本和可用跳转。
- [ ] 流式 SSE 先返回 metadata/source 事件，再返回 delta，最后返回 done；流式与非流式字段语义保持一致。

## 三、RAG 核心技术 TODO

### P0：正确性和可复现性

- [ ] 禁止正式环境静默退化到 hash embedding；增加显式 `allow_hash_fallback`，默认关闭。
- [ ] 将 SentenceTransformer 运行依赖纳入可安装依赖，并在启动时报告实际 embedding backend。
- [ ] 建立索引 manifest，记录语料版本、Git commit、JSON revision、embedding 模型与维度、query instruction、切块参数、向量归一化、chunk 数、metadata 哈希和构建时间。
- [ ] 服务启动时校验 manifest、FAISS 维度、metadata 数量与哈希；不匹配时进入 `rag_not_ready`，不得带病查询。
- [ ] 索引采用版本化目录和原子切换，防止 `index.faiss` 与 `metadata.jsonl` 分别更新造成错配。
- [ ] 排除 LICENSE 等无业务价值文件；同一资料同时存在结构化正文、Markdown 和 PDF 时只选权威版本。
- [ ] 为缺索引、索引损坏、维度不匹配、embedding 失败、无结果、超时和权限不足定义统一错误码与可读降级响应。

### P0：图谱作为唯一逻辑起点

- [ ] 建立知识点定位索引，覆盖标准名称、别名、英文名、符号、章节和检索关键词。
- [ ] 查询首先返回 Top-3 知识点候选及定位分数；有页面 `course_id/knowledge_point_id` 上下文时优先使用并验证权限。
- [ ] 低置信度或同名异义时发起澄清，不直接跨课程召回材料。
- [ ] 按问题类型扩展前置、后置、应用和跨课程关系，并记录每个扩展节点的理由。
- [ ] 文档检索必须带允许的课程、知识点和来源层级过滤条件；外部辅助信息不得覆盖官方正文和课程语境。
- [ ] 图谱定位和关系扩展结果写入响应 `graph_context`，便于前端高亮和跳转。

### P1：切块、召回和重排

- [ ] 将固定 800 字符切块升级为“章节/段落优先，超长段落再按 token 切分”。
- [ ] chunk metadata 保存课程、知识点、material ID、标题路径、页码、字符区间、来源层级、内容哈希和相邻 chunk ID。
- [ ] 建库前按内容哈希去重；检索后合并相邻 chunk，并限制单一文档占据的候选数量。
- [ ] 先召回较大候选集，再使用 BGE reranker 或同等级轻量重排器选出最终上下文。
- [ ] 增加最低相关性阈值；无充分证据时返回“未找到足够课程资料”，而不是强行使用 Top-K。
- [ ] 对多轮追问进行 query rewrite，但保留原始 query、改写 query 和 trace，方便调试。
- [ ] 按模型 token 预算动态拼装上下文，不只按固定 chunk 数截断。

### P1：回答、引用和安全

- [ ] 将检索文本标记为“不可信资料数据”，禁止执行资料中的命令性文本，降低 prompt injection 风险。
- [ ] 生成提示词明确区分“资料事实”“基于资料的推理”“需要确认的信息”。
- [ ] 要求关键事实使用 citation ID；返回 sources 前检查引用 ID 必须来自本次候选集。
- [ ] citation 返回真实片段和站内对象 ID，不由模型自由生成 URL；前端根据对象 ID 构造已注册路由。
- [ ] 三种模式共享事实和引用规则，但输出目标不同：快速问答强调结论，引导学习强调层级与问题，深入探究强调跨关系、推导和延伸。
- [ ] 深入探究模式接收自主学习星状态；无星时只增加学习顺序提示，不禁止进入，也不自动授星。

### P1：可观测性

- [ ] 每次调用记录图谱候选、查询改写、召回结果、重排结果、阈值过滤、模型/提示词版本、各阶段耗时、Token、错误和反馈。
- [ ] 日志只保存授权范围内的必要数据，用户私有学习记录与公共课程索引隔离。
- [ ] `/health` 保留进程健康；新增 readiness 信息，显示索引版本、真实 embedding backend、资料版本和加载状态。
